# 抓取技巧记录

本文件记录本次按 `ref/ref.md` 批量归档资料时验证过的抓取方法，供后续类似任务复用。

## 基本原则

- 先按 `ref/ref.md` 的分类建目录，例如 `论文/`、`博客/`、`教程/`、`书籍/`、`合集/`。
- 每条网页资料单独建子目录，至少保留：
  - `source-url.txt`：原始链接。
  - 原始抓取日志，例如 `wget.log`、`curl.log`、`chrome-convert.log`。
  - 原始或渲染后的 HTML，例如 `chrome-captured.html`。
  - 整理后的 Markdown，例如 `content.md`。
  - 如有图片，保留 `media-urls.txt`、`media-map.tsv`、`media-download.log` 和 `media/`。
- 先抓原始材料，再做 Markdown 转换；不要只保存整理稿。
- 图片优先下载本地副本。即使 Markdown 中保留远程 URL，也要尽量保留 `media/` 目录。
- 如果某个站点失败，要保留失败页和日志，便于判断是网络、登录、反爬、403 还是 SSL 问题。

## 开源项目

- GitHub 仓库要完整 clone，不用浅克隆。
- 如果先前已误用 `--depth 1`，用 `git fetch --unshallow --tags` 补完整历史。
- 直连 GitHub 超时时，可以临时使用可访问的 GitHub 代理下载；下载后把 `origin` 改回原始 GitHub URL。
- 验证命令：

```bash
git -C <repo-dir> rev-parse --is-shallow-repository
git -C <repo-dir> remote get-url origin
```

## PDF / 论文

- 直接用 `curl -L --fail --retry 2 -o ...` 保存 PDF。
- 文件名优先使用 arXiv ID 或论文 ID，便于回查来源。
- PDF 归档时保留原始 URL 在说明文档中。

## 普通网页

首选 `wget` 离线抓取：

```bash
wget --page-requisites \
  --convert-links \
  --adjust-extension \
  --span-hosts \
  --execute robots=off \
  --user-agent="Mozilla/5.0 ..." \
  --tries=2 \
  --timeout=45 \
  --waitretry=2 \
  --content-on-error \
  --no-verbose \
  -P <target-dir> \
  <url>
```

适合静态页面、公司博客、公众号等。优点是会顺带下载页面引用的图片、CSS、脚本；缺点是 JS 渲染页、登录页、反爬站点可能失败。

## 已登录 Chrome 抓取

当 `wget` / `curl` 失败，但浏览器能打开时，用 Chrome 渲染抓取：

1. 在 Chrome 中登录目标站点。
2. 打开 Chrome 菜单：`View` -> `Developer` -> `Allow JavaScript from Apple Events`。
3. 使用 AppleScript 打开目标 URL、等待加载、滚动触发懒加载，然后导出 `document.documentElement.outerHTML`。
4. 用 HTML 转 Markdown 脚本生成 `content.md`。

本次验证过：

- Medium 直连超时，但已登录 Chrome 可以抓到正文。
- Substack 直连超时，但 Chrome 渲染可以抓到正文。
- `walkinglabs.github.io` 的 `wget` SSL 失败，但 Chrome 渲染可以抓到正文。
- BestHub 即使用 Chrome 仍返回 403，说明不是简单登录或 JS 渲染问题。

本次临时使用过两个辅助脚本：`capture_chrome_html.applescript` 和 `medium_html_to_markdown.ts`。它们放在 `raw/` 根目录，但按本仓库规则不入库；后续需要时可按本节描述重建。

## Medium

- `curl` / `wget` 到 Medium 可能超时，`?format=json` 也可能不可用。
- 登录 Chrome 后用 AppleScript 抓渲染 HTML，成功率更高。
- 从渲染 HTML 转 Markdown 时，如果图片本地化卡住，先生成 Markdown，再单独下载图片。
- Medium 图片域名 `miro.medium.com` 在 shell 中可能超时，可以用图片代理：

```text
https://wsrv.nl/?url=<原始图片URL>
```

- 每条 Medium 建议保留：
  - `chrome-captured.html`
  - `content.md`
  - `media-urls.txt`
  - `media/`
  - `media-map.tsv`

## X / Twitter

- 抓取 X 内容需要用户明确同意使用非官方、反向工程接口。
- 官方技能脚本需要 `auth_token` 和 `ct0`，如果本机 Chrome 没有可读登录态，会失败。
- 对公开推文/文章，可以用 `api.fxtwitter.com/status/<id>` 保存公开 JSON。
- 每条建议保存：
  - `source-url.txt`
  - `api-url.txt`
  - `fxtwitter.json`
  - `content.md`
  - `all-urls.txt`
  - `media-urls.txt`
  - `media/`
- `pbs.twimg.com` 直连可能超时，可以用：

```text
https://wsrv.nl/?url=<原始图片URL>
```

## Substack

- `curl` / `wget` 可能连接超时。
- 浏览器能打开时，优先使用已登录 Chrome 渲染抓取。
- Substack HTML 中图片尺寸变体很多；为了 PPT 参考，可以保留全部变体，并用 `media-map.tsv` 记录来源。

## 失败判断

- `HTTP 403`：通常是站点拒绝访问，换真实浏览器仍 403 时，可判定为受限。
- `Connection timed out`：优先尝试已登录 Chrome 或换网络路径。
- `SSL connection failed`：优先尝试 Chrome 渲染抓取。
- `Cloudflare Just a moment`：等待浏览器验证完成后重试，必要时让用户手动通过验证。
- `content.md` 行数很少且标题是 `Just a moment...`、`Access denied`、`HTTP ERROR 403` 时，不应视为成功正文。

## 收尾验证

完成后至少检查：

```bash
find raw -type f | wc -l
find raw -type f | rg -i '\\.(png|jpe?g|gif|webp|svg)(\\?|$)' | wc -l
find raw -name content.md | wc -l
ps -axo pid,ppid,stat,command | rg 'wget|curl|osascript|git clone|fetch --unshallow' || true
```

仓库级检查仍按 `AGENTS.md` 执行：

```bash
git status --short
git diff -- AGENTS.md CLAUDE.md materials greenpower
rg -n "TODO|FIXME" materials greenpower
rg -n "API Key[:：]\\s*sk-" materials greenpower AGENTS.md
```
