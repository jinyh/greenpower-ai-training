# 讲师快速参考卡

> **用途**：工作坊当天随身携带的一页纸速查
> **核心**：关键概念、常见翻车场景、时间应急方案

---

## 一、三要素一句话总结

| 要素 | 一句话 | 核心问题 |
|------|--------|---------|
| **Prompt** | 给 Agent 的"任务书" | "你要做什么、给谁看、输出什么格式" |
| **Context** | Agent 的"视野"和"记忆" | "你能看到什么、知道什么、记得什么" |
| **Harness** | 让 Agent "不跑偏"的护栏 | "你不能做什么、必须怎么做、不确定时怎么办" |

**核心公式**：
```
驾驭 Agent = 设计好任务（Prompt）+ 管理好信息（Context）+ 设定好规则（Harness）
```

## 二、全天时间线速查（方案 A′）

| 时间 | 环节 | 关键动作 |

- 若下午实战不够：取消休息，或汇报缩至4分钟/组

## 三、常见翻车场景 & 应对话术

### 场景1：Agent 编造数据（幻觉）

**表现**：Agent 自信地给出精确但不存在的数字

**应对话术**：
> "大家看这里，Agent 说'预计Q4营收增长15%'——材料里有这个预测吗？没有。它'幻觉'了。这就是为什么边界约束是必须的：'只基于给定材料，不要补充外部信息'。"

**预防措施**：
- Prompt 中加边界约束
- 要求 Agent 标注数据来源
- 人工核实关键数字

---

### 场景2：Agent 跑偏

**表现**：输出和任务无关，或聊着聊着话题漂移

**应对话术**：
> "Agent 现在跑到技术细节里去了，但我们的任务是财务分析。这通常是因为 Prompt 的目标不够聚焦。试试把 Objective 拆成更具体的子任务，或者在一轮对话太长时，重置核心目标。"

**预防措施**：
- Prompt 中 Objective 要具体
- 长对话中定期重置目标
- 用 Harness 约束话题范围

---

### 场景3：Agent 输出太长/太散

**表现**：信息淹没在大段叙述中，无法快速提取要点

**应对话术**：
> "Agent 给了我一篇2000字的分析，但我只有3分钟看。这就是为什么格式约束如此重要：'用表格呈现''每条洞察不超过40字''先给结论再给论据'。"

**预防措施**：
- 指定输出格式（表格/bullet points）
- 限制字数（"每条不超过40字"）
- 要求"结论先行"

---

### 场景4：Agent 遗漏关键信息

**表现**：没提取用户最关心的指标或忽略了反面证据

**应对话术**：
> "Agent 没提现金流的问题，但这是我们最关注的。这通常是因为 Context 投喂不够精准，或者 Prompt 没明确要求'列出所有风险因素'。"

**预防措施**：
- Prompt 中明确列出要提取的指标
- 要求"列出所有风险因素"
- 要求"列出你可能遗漏的关键因素"

---

### 场景5：Agent 语气不对

**表现**：输出太学术、太口语、或不符合受众预期

**应对话术**：
> "这个分析写得像 Wikipedia，但我们是写给投委会看的。记住 Prompt 里的 Audience 要素：'面向投委会，他们熟悉财务术语但时间有限'。同样的分析，给实习生看和给投委会看，应该是完全不同的。"

**预防措施**：
- Prompt 中定义 Audience
- 定义 Style 和 Tone
- 用项目规则文件（OpenCode 常用 `AGENTS.md`，Claude Code 常用 `CLAUDE.md`）统一风格

---

### 场景6：网络/API 故障

**表现**：OpenCode / Claude Code 能启动，但模型无响应；或 Provider / 账号配置错误

**应对话术**：
> "这类问题现场不要无限排查。先检查 Key、Base URL、模型名和额度；2分钟内解决不了，就先两人一机，保证学习任务不中断。"

**预防措施**：
- 课前登记每位学员使用 OpenCode 还是 Claude Code
- OpenCode 路径锁定课堂 Provider、Base URL 和模型名
- 准备一个备用 Provider
- 准备离线数据集作为保底

---

### 场景7：学员说"Agent 没什么用"

**表现**：学员尝试了简单的 Prompt，输出质量低，感到失望

**应对话术**：
> "第一次失望是正常的。Agent 不是魔法，它需要你的引导。试着调整 Prompt——加上 Audience、加上格式约束、加上边界限制——你会发现第二次好很多。"

**引导方法**：
- 现场帮学员改进 Prompt
- 展示改进前后的输出对比
- 强调"迭代"是常态

---

### 场景8：学员过于兴奋，想完全依赖 Agent

**表现**：学员认为 Agent 可以替代人工判断

**应对话术**：
> "Agent 可以帮你写初稿，但签字的是你。最终的责任，永远在人的肩上。Agent 的价值不是'替代分析师'，而是'让分析师把精力放在判断上，而不是搬运数据上'。"

**引导方法**：
- 展示 Agent 的翻车案例
- 强调人工复核的必要性
- 用"杠杆"而非"替代"的比喻

## 四、三要素检查清单（现场用）

### Prompt 检查（问学员）

- [ ] 目标清晰吗？Agent 知道要完成什么具体任务吗？
- [ ] 背景充分吗？Agent 了解前因后果和约束条件吗？
- [ ] 受众明确吗？Agent 知道输出给谁看、用什么语气吗？
- [ ] 格式指定了吗？Agent 知道输出什么形式吗？
- [ ] 约束到位了吗？Agent 知道不能做什么、不确定时怎么办吗？

### Context 检查（问自己）

- [ ] 提供的材料是否相关、准确、结构化？
- [ ] 是否需要拆分成多个会话？
- [ ] 项目规则文件是否已定义角色、风格、禁忌？
- [ ] 信息密度是否适中？

### Harness 检查（问学员）

- [ ] 有明确的边界约束吗？
- [ ] 有具体的格式要求吗？
- [ ] 有防幻觉机制吗？
- [ ] 有校验机制吗？
- [ ] 输出是否稳定可控？

## 五、核心教学金句

| 场景 | 金句 |
|------|------|
| 开场 | "Agent 不是来替代你的判断力的，而是来放大你的执行力的。" |
| Prompt | "Prompt 不是提问，而是一份结构化的任务指令书。" |
| Context | "管理 Context 的本质，是管理 Agent 的'视野'和'记忆'。" |
| Harness | "Harness 是安全带，不是枷锁。好的 Harness 让 Agent 更快更准。" |
| 翻车 | "Agent 不'知道'自己不知道。这就是为什么要加边界约束。" |
| 校验 | "永远假设 Agent 会犯错。边界约束、校验机制、人工复核——三道防线。" |
| 总结 | "Agent 是杠杆，不是替代。质量80%取决于你的 Prompt，15%取决于 Context，5%取决于模型。" |

## 六、工具操作速查

### 终端 Agent 课堂验证

1. 终端执行其中一个：
   ```bash
   opencode --version
   claude --version
   ```
2. 启动对应工具：
   ```bash
   opencode
   # 或
   claude
   ```
3. 发送：
   ```text
   请用一句话确认你已正常响应。
   ```
4. 若无响应，优先检查：API Key、Base URL、模型名、账号额度。

### 项目规则文件

OpenCode 常用 `AGENTS.md`，Claude Code 常用 `CLAUDE.md`。课堂统一讲“项目规则文件”，示例：

```markdown
# AGENTS.md
## 角色
你是某投研机构资深分析师。
## 禁忌
- 不编造未公开财务数据
- 不给买入/卖出建议
```

### Claude Code 路径说明

适合已有 Claude Code 访问条件、网络稳定的老师或学员：

```bash
claude --version
claude
```

强调：Claude Code 和 OpenCode 在本课核心工作流上差别不大；选择哪个工具，不影响 Prompt / Context / Harness 的学习目标。

### MCP 概念

MCP 是给 Agent 接入外部工具和数据源的方式。当天只讲概念和价值，不要求所有小组现场配置 MCP。
