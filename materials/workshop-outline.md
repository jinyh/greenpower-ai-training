## 核心概念：什么是 Agent

本课所说的 Agent，不是简单的聊天机器人，而是一个能围绕目标持续推进任务的 AI 工作单元。

```text
传统 ChatGPT：
人提问 -> AI 回答 -> 人继续追问

终端 Agent：
人设定目标 -> Agent 读取材料 -> 拆分步骤 -> 调用工具 -> 生成结果 -> 人工校验
```

一个 Agent 通常由四部分组成：


| 组成      | 含义         | 课堂中的例子               |
| ------- | ---------- | -------------------- |
| 模型      | 负责理解、推理和生成 | 通义、DeepSeek、Claude 等 |
| 工具      | 负责“动手”     | 读写文件、搜索、运行命令、调用 API  |
| Context | 负责“看见什么”   | 上传材料、对话历史、项目规则文件     |
| Harness | 负责“不能跑偏”   | 不编造、不越界、标注不确定、输出自检   |


所以，Agent 的价值不是“替人做判断”，而是把资料整理、初稿生成、格式转换、反复校验等执行性工作提速。最终判断、取舍和责任仍然在人。

## Prompt / Context / Harness 的关系

```text
                 +----------------------+
                 |        Agent          |
                 |  读材料、调工具、      |
                 |  分步骤执行任务        |
                 +----------+-----------+
                            |
                            v
        +-------------------+-------------------+
        |                                       |
        v                                       v
+---------------+                     +----------------+
| Prompt        |                     | Context        |
| 任务指令书     |                     | Agent 的视野    |
| 要做什么       |                     | 能看到什么材料   |
| 给谁看         |                     | 记得什么背景     |
| 输出什么格式   |                     | 可用什么工具     |
+-------+-------+                     +--------+-------+
        |                                      |
        +------------------+-------------------+
                           v
                  +----------------+
                  | Harness        |
                  | 规则和护栏      |
                  | 不能做什么      |
                  | 如何标注不确定  |
                  | 如何自检        |
                  +--------+-------+
                           |
                           v
                  +----------------+
                  | Output         |
                  | 可用但需人工复核 |
                  +----------------+
```

三者的分工：


| 要素      | 回答的问题              | 如果缺失，会发生什么       |
| ------- | ------------------ | ---------------- |
| Prompt  | 要做什么、给谁看、输出什么格式    | 输出泛泛而谈，像搜索摘要     |
| Context | 基于哪些材料、背景和工具来做     | 信息不足或信息过载，容易跑偏   |
| Harness | 不能做什么、不确定时怎么办、如何校验 | 容易幻觉、越界、给出不可审计结论 |

## 详细讲稿与教学要点

### 上午扩充讲法总则

上午不是把 Prompt / Context / Harness 三个概念"讲完"，而是让学员在 3 小时内形成一个稳定的工作动作：

```text
先把任务说清楚 -> 再决定给 Agent 看什么 -> 最后加规则防止跑偏 -> 人做复核
```

每个 30 分钟概念模块建议都按同一个节奏展开，降低非技术学员的认知负担：


| 分钟    | 教学动作    | 讲师目标                  |
| ----- | ------- | --------------------- |
| 0-5   | 用业务类比引入 | 把抽象概念落到管理场景           |
| 5-12  | 拆解概念结构  | 给学员一套可复用框架            |
| 12-20 | 对比演示    | 让学员亲眼看到"差指令"和"好指令"的差距 |
| 20-25 | 追问与纠偏   | 引导学员发现错误，而不是直接告诉答案    |
| 25-30 | 跟练与收束   | 让学员完成一个很小但完整的动作       |


讲师可以反复使用三句过渡话：

1. "我们先不追求一次做对，先让它犯一个有教学价值的错。"
2. "现在的问题不是模型不够聪明，而是我们给它的任务、材料或规则不够清楚。"
3. "Agent 的输出不是终点，而是下一轮判断和修正的起点。"

上午板书建议：

```text
Prompt  = 任务书：做什么、给谁看、交付什么
Context = 资料包：基于什么材料、记住什么背景
Harness = 风控线：不能做什么、错了怎么暴露

质量公式：输出质量 = 任务清晰度 x 信息质量 x 约束强度 x 人工复核
```

### 09:00-09:20 破冰与导入（20分钟）

#### 开场白建议

> "大家好，我是来自上海交大人工智能研究院的[姓名]。今天我们不讲算法，不讲代码，讲的是——**怎么让 AI 像你的实习生一样帮你干活**。
>
> 在座各位有做投资研究的、有做产业分析的、也有做运营管理和市场推广的。不管你的岗位是什么，你们的时间都很贵，但每天可能有 30%-50% 花在信息整理、材料撰写、数据搬运这些重复性工作上——可能是写会议纪要、做周报、整理财报、搜集竞品信息、做 PPT。今天的工作坊，目标就是让你们带走一个认知：**Agent 不是来替代你的判断力的，而是来放大你的执行力的。**"

#### 三个关键对比（PPT建议）


| 对比维度 | 传统 ChatGPT | 终端 Agent（Claude Code / OpenCode） |
| ---- | ---------- | -------------------------------- |
| 交互方式 | 一问一答，人驱动   | 多步骤自主执行，人设定目标                    |
| 能力边界 | 只动嘴（生成文字）  | 能动手（读写文件、运行代码、调用工具）              |
| 使用门槛 | 需要人持续输入    | 一次设定，自主完成复杂任务链                   |
| 错误模式 | 说错话（幻觉）    | 做错事（文件覆盖、数据误读），需人工校验             |


#### 今日承诺

> "今天结束时，我希望每个人都能回答三个问题：
>
> 1. Agent 能帮我做什么？（能力边界）
> 2. Agent 不能帮我做什么？（能力盲区）
> 3. 我怎么让它做得更好？（驾驭方法）"

#### 课堂纪律

- 上午请跟随演示操作，有问题随时举手
- 下午小组实战，每组需要一个"记录员"记录迭代过程
- 手机静音，但鼓励拍照记录关键屏幕

#### 扩展讲解包：为什么今天讲 Agent，而不是只讲 ChatGPT

**讲师话术**：

> "如果只把 AI 当成聊天窗口，大家会自然地问：'这个问题怎么问得更好？'但 Agent 时代的问题变了。我们要问的是：'我能不能把一个工作流交给 AI，让它帮我读材料、拆步骤、生成中间产物，并且在我设定的边界内推进？'"

可以用三个业务场景解释差异：


| 业务场景 | 普通聊天工具     | 终端 Agent                   |
| ---- | ---------- | -------------------------- |
| 会议纪要 | 粘贴文字后让它总结  | 读取会议稿文件，生成纪要、行动项、风险点，并写入文件 |
| 财报初筛 | 问"这家公司怎么样" | 读取财报节选，按指标提取、标注来源、列出待核实数据  |
| 竞品分析 | 让它泛泛比较几家公司 | 读取多份资料，生成对比矩阵，指出材料缺口       |


**现场提问**：

> "如果你有一个很认真但刚入职的实习生，你最担心他犯哪三类错误？"

预期回答与引导：


| 学员回答  | 讲师引导到             |
| ----- | ----------------- |
| 不知道重点 | Prompt：任务和受众没讲清楚  |
| 材料看漏  | Context：资料包和重点不清楚 |
| 自作主张  | Harness：边界和校验没设好  |
| 做得慢   | Agent 的价值：提速执行性工作 |


**PPT 页面建议**：

1. 第 1 页：标题 + 今日主线："Agent 是杠杆，不是替代"
2. 第 2 页：ChatGPT vs Agent 对比表
3. 第 3 页：Prompt -> Context -> Harness 总图
4. 第 4 页：上午目标：看懂、会问、会约束、会复核

**开场小案例（可选 3 分钟）**：

给出同一任务：

```text
帮我做一份新能源行业分析。
```

追问学员：

- 这句话里缺什么？
- 谁要看这份分析？
- 基于哪些材料？
- 能不能给投资建议？

> "这五个问题，就是今天上午的全部内容。我们不是学一堆技巧，而是建立一套管理 Agent 的工作习惯。"

### 09:20-09:50 三要素讲解：Prompt（30分钟）

#### 概念引入（4分钟）

**类比**：

> "Prompt 就是你给下属布置工作时说的话。但大多数人对 AI 的说话方式，还停留在'搜索引擎时代'——输入关键词，期待一个完美答案。对 Agent 来说，这远远不够。"

**定义**：

> "Prompt 是一份**结构化的任务指令书**。它告诉 Agent：**你要做什么、给谁看、做到什么程度、输出什么格式、不能踩哪些红线**。

#### Prompt 结构拆解（8分钟）

推荐教学框架（简化版 CO-STAR）：


| 要素            | 英文  | 含义         | 示例                                   |
| ------------- | --- | ---------- | ------------------------------------ |
| **C**ontext   | 背景  | 这个任务的前因后果  | "我们是某私募基金的投研团队，正在评估宁德时代2024年Q3的投资价值" |
| **O**bjective | 目标  | 具体要达成什么    | "提取财报中的5个核心财务指标，并与比亚迪、LG新能源进行横向对比"   |
| **S**tyle     | 风格  | 输出的语气和专业程度 | "用资深分析师的口吻，数据驱动，避免主观臆断"              |
| **T**one      | 语调  | 情感色彩       | "客观、冷静、略带审慎"                         |
| **A**udience  | 受众  | 给谁看        | "面向投资委员会，他们熟悉财务术语但时间有限"              |
| **R**esponse  | 格式  | 输出形式       | "Markdown表格呈现对比数据，最后附3条投资亮点和3条风险提示"  |


**课堂补充：CO-STAR 不必每次都写满**

> "CO-STAR 不是填表考试，而是一张检查清单。简单任务可以只写 Objective + Response + Constraint；高风险任务至少要写 Context + Objective + Audience + Constraint。"


| 任务风险            | 最少要写清楚                                         | 示例                      |
| --------------- | ---------------------------------------------- | ----------------------- |
| 低风险：改写邮件、整理提纲   | Objective、Response                             | "把这段话改成正式邮件，保留事实，不新增内容" |
| 中风险：市场调研、竞品对比   | Context、Objective、Audience、Response            | "面向管理层，输出对比矩阵和机会点"      |
| 高风险：投资、政策、财务、法务 | Context、Objective、Audience、Response、Constraint | "只基于给定材料，不给交易建议，列出不确定点" |


#### 现场演示（10分钟）

**演示任务**：让 Agent 分析一句话的公司描述

**步骤1：展示"烂Prompt"**

```
帮我分析一下这家公司。
```

**预期结果**：Agent 输出泛泛而谈，没有聚焦，没有结构。

> "大家看，Agent 确实给出了一些信息，但像一份 Wikipedia 摘要，对我们的投资决策没有直接帮助。问题出在：我们没有给它**目标、受众和格式约束**。

**步骤2：展示"好Prompt"**

```
背景：我们是某私募基金投研团队，正在评估新能源汽车电池赛道的头部企业。

任务：基于公开信息，对宁德时代进行商业模式分析。

要求：
1. 用商业模式画布（Business Model Canvas）的9个模块进行结构化呈现
2. 每个模块至少列出2个关键要点
3. 对不确定的信息，标注[推测]
4. 最后附一段200字的投资价值摘要，面向投资委员会
5. 输出格式：Markdown表格 + 文字段落

约束：只基于公开可验证的信息，不要编造未公开的财务数据或合作细节。
```

**预期结果**：输出结构清晰、模块完整、有标注、有摘要。

> "对比这两个输出，你们看到了什么？第二个 Prompt 字数是第一个的10倍，但产出的价值可能是100倍。这不是因为 Agent 变聪明了，而是因为我们给了它**跑道**。

#### 扩展演示脚本：从一句话任务到可执行任务书（8分钟备用）

讲师可以在屏幕上逐步改同一个 Prompt，每次只加一个要素，让学员观察输出变化。

**版本 0：只有愿望**

```text
帮我分析一下低空经济。
```

讲师点评：

> "这不是任务，而是愿望。Agent 会给你一篇看似完整、但不可用的百科式回答。"

**版本 1：加 Objective**

```text
任务：请判断低空经济在未来 3 年可能出现的 3 类商业化场景。
```

观察点：输出开始有方向，但可能泛泛。

**版本 2：加 Audience**

```text
受众：面向一家制造业集团的战略投资部，他们关心是否需要布局相关产业链。
```

观察点：输出会更接近业务决策，而不是科普文章。

**版本 3：加 Response**

```text
输出：用表格呈现，列为：场景、需求来源、可能受益环节、关键不确定性、需要补充的信息。
```

观察点：结构明显提升，便于讨论。

**版本 4：加 Constraint**

```text
约束：只基于我提供的材料；材料未提及的数据请标注[待核实]；不要预测具体市场规模。
```

观察点：Agent 更愿意暴露不确定，不再强行给数字。

**讲师追问**：

- "哪一步让输出从'文章'变成了'工作成果'？"
- "哪一步最能降低幻觉风险？"
- "如果这个输出要给董事会看，还需要补什么？"

**标准收束**：

> "Prompt 的本质不是写得长，而是把管理者脑子里的隐性要求显性化。你不说，Agent 就会自己猜；它一猜，就可能跑偏。"

**备选演示：行政/运营场景（讲师可根据学员反应切换）**

如果课堂中运营/行政背景学员较多，可用以下场景替代或补充"低空经济"演示：

**版本 0：只有愿望**

```text
帮我整理一下上周的活动情况。
```

**版本 1-4 逐步加结构**：

```text
任务：请基于我提供的活动签到表和反馈问卷，生成一份活动总结。

受众：面向部门主管，他们关心参与率、满意度和改进建议。

输出：用表格呈现关键数据（报名人数、实到人数、满意度评分），再列 3 条改进建议。

约束：只基于我提供的数据；满意度评分直接引用问卷结果，不要自行推算或编造。
```

讲师点评："同样的逻辑——从愿望到任务书，从模糊到可交付。不管你做的是行业研究还是活动总结，结构化 Prompt 的方法是一样的。"

#### 教学要点总结（3分钟）

- **Prompt 的长度 ≠ 复杂度**：关键是有结构，不是堆字数
- **约束比自由更重要**：对 Agent 来说，"不能做什么"往往比"要做什么"更能提升质量
- **Audience 是最容易被忽略的要素**：同样的分析，给投委会看和给实习生看，输出应该完全不同

#### 学员跟练（5分钟）

> "请打开你们手机上的通用 AI 网页版，或课前已装好的 OpenCode / Claude Code——任选其一。把下面这句烂 Prompt 发出去，看输出；再改成加上 **Objective + Audience + 一条 Constraint** 的版本，对比差异。不必追求完美，感受'结构'带来的变化即可。"

**跟练任务**：用各自熟悉的一家公司（或下午想做的行业），写一句「烂 Prompt」→ 改一版「加结构 Prompt」（至少含 O、A、一条 Constraint）。

**讲师巡视话术**："Audience 写清楚了吗？Constraint 里有没有'不要编造'？"

#### Prompt 模块常见学员错误与纠偏


| 常见错误  | 现场表现         | 讲师追问               | 推荐纠正                       |
| ----- | ------------ | ------------------ | -------------------------- |
| 目标太大  | "帮我分析行业趋势"   | "分析给谁看？要做什么决策？"    | 缩成一个可交付产物，如"3 个机会 + 3 个风险" |
| 受众缺失  | 输出像百科或新闻稿    | "这个结果是给老板、客户还是同事？" | 加 Audience 和语气要求           |
| 格式缺失  | 输出很长、无法扫描    | "你希望 3 分钟内看完吗？"    | 指定表格、字数、标题结构               |
| 约束缺失  | Agent 自信补充事实 | "这些数字来自哪里？"        | 加"只基于材料、未提及则标注"            |
| 一次问太多 | 结果面面俱到但浅     | "哪个问题最影响决策？"       | 拆成收集、分析、输出三轮               |

### 09:50-10:20 三要素讲解：Context（30分钟）

#### 概念引入（5分钟）

**类比**：

> "Context 就是你给下属提供的'背景资料包'。给少了，他做决策时信息不足；给多了，他会迷失重点。更关键的是，Agent 有'失忆'问题。"

**核心问题**：

> "Agent 能'记住'多少？—— 这取决于它的**上下文窗口**（Context Window）。超出这个窗口，早期的信息会被'遗忘'。所以，**管理 Context 是管理 Agent 能力的关键**。

#### 上午重点：两种 Context（15分钟）

> **说明**：Context 在概念上有四种类型；**上午先讲最常用的两种**（外部 + 对话）。系统配置（项目规则文件，如 `AGENTS.md` / `CLAUDE.md`）和工具扩展（MCP）在 **11:05 环境段**结合终端 Agent 现场演示。

**类型1：外部 Context（你主动给 Agent 的文件/数据）**

> "这是最直接的 Context。你上传一份财报PDF，Agent 就能基于它分析。但这里有技巧——"

- **文件 vs 文本**：PDF 需要解析，可能有格式损失；纯文本更可控
- **信息密度**：给 Agent 一份100页的招股书，它可能迷失在细节中；先给一份5页的摘要，再按需深入
- **结构化数据**：CSV/Excel 比纯文本更容易让 Agent 做计算和对比

**现场演示**：

- 先不给行业背景，让 Agent 分析某家公司的商业模式 → 输出泛泛
- 补充一句话行业 Context（"这是2024年的新能源行业，面临产能过剩"）→ 输出立刻聚焦

**类型2：对话 Context（历史对话的累积）**

> "Agent 能'记得'你们之前说了什么。但这个记忆是有限的。"

- **长对话的陷阱**：聊了50轮后，Agent 可能"忘记"你第一轮给的任务目标
- **应对方法**：定期"重置 Context"——在关键节点重复核心目标；或开启新会话

#### 扩展讲解包：Context 不是"多给材料"，而是"给对材料"

**讲师话术**：

> "很多人第一次用 Agent 做研究，会把所有资料一股脑丢进去。这就像把 300 页材料扔给实习生，然后说'你看着办'。信息多，不等于 Context 好。好的 Context 有三个特点：相关、结构化、可追溯。"


| Context 质量 | 低质量做法    | 高质量做法                            |
| ---------- | -------- | -------------------------------- |
| 相关性        | 上传所有资料   | 只给和当前任务相关的章节                     |
| 结构化        | 大段复制粘贴   | 先列材料目录、来源、日期、用途                  |
| 可追溯        | "据说市场很大" | "材料 A 第 2 段提到政策方向，材料 B 表格列出企业对比" |


**板书：三层 Context**

```text
第 1 层：任务背景（为什么做）
第 2 层：资料清单（基于什么做）
第 3 层：引用规则（怎么证明不是编的）
```

**示例：同一段材料的两种投喂方式**

低质量 Context：

```text
这里有一堆关于储能行业的资料，请帮我分析。
```

高质量 Context：

```text
Context：
1. 材料 A 是某省储能政策节选，重点看补贴条件和并网要求。
2. 材料 B 是三家储能公司的产品介绍，重点看商业模式和客户类型。
3. 材料 C 是一段客户访谈，重点看采购顾虑。

请只基于这三份材料，分析"工商业储能销售"的机会和阻碍。
每条结论后标注来自 A/B/C 哪份材料。
```

**现场提问**：

- "如果你只能给 Agent 一页纸，你会放什么？"
- "哪些材料应该先不给，等 Agent 需要时再给？"
- "哪些内容是事实，哪些只是你的判断？Agent 能分清吗？"

**讲师收束**：

> "Context 管理的第一步，是把事实、假设、问题分开。Agent 最容易出错的地方，就是把你的假设当成事实，把材料缺口当成可以自由发挥的空间。"

#### 扩展演示：长对话失忆与重置（5分钟备用）

演示步骤：

1. 第一轮给出任务："基于材料整理 3 个客户痛点，不要提解决方案。"
2. 第二至四轮不断追问技术、产品、竞品。
3. 第五轮让 Agent 输出总结，观察它是否开始加入解决方案或忘记边界。
4. 加入重置语句：

```text
请回到最初任务：只整理客户痛点，不提出解决方案。
请忽略刚才关于产品方案的讨论，把输出重新整理为三列表格：
痛点 | 材料依据 | 仍需确认的问题。
```

讲师点评：

> "长对话不是越长越聪明。复杂任务要阶段性归档，把关键目标重新说一遍。"

#### 教学要点总结（5分钟）

- **Context 的质量 > 数量**：给 Agent 10份杂乱的材料，不如给1份整理好的摘要
- **上下文窗口是硬约束**：长任务要拆分成短会话，关键信息要反复提及
- **预告**：系统 Context（项目规则文件）和工具 Context（MCP）在休息后的环境段演示——那是「一次配置、长期生效」的杠杆

#### 学员跟练（5分钟）

> "继续用刚才的 Prompt。这一次**只改 Context**：第一轮不加任何行业背景；第二轮在 Prompt 前加 2–3 句行业 Context（如产能过剩、政策补贴退坡）。对比两次输出，哪次更'像给投委会看的'？"

**讲师巡视话术**："你们第二次加的 Context，是'事实'还是'观点'？Agent 分得清吗？"

#### Context 模块跟练升级版（时间充裕时）

让学员把自己的 Context 分成三栏：


| 事实材料          | 我的判断/假设        | 希望 Agent 帮我判断的问题 |
| ------------- | -------------- | ---------------- |
| 已有报告、访谈、数据、网页 | 行业趋势、客户偏好、风险猜测 | 需要提取、比较、归纳、验证的内容 |


要求：

1. 至少列 2 条事实材料
2. 至少列 1 条自己的假设
3. Prompt 中明确告诉 Agent："假设不等于事实"

讲师巡视话术：

> "你这句话是材料里写的，还是你自己的判断？如果是判断，要不要让 Agent 帮你找反证？"

### 10:20-10:50 三要素讲解：Harness（30分钟）

#### 概念引入（5分钟）

**类比**：

> "Harness 就是公司的 SOP（标准作业程序）和风控红线。Agent 能力很强，但也容易'幻觉'——编造不存在的信息，或'跑偏'——偏离你的真实需求。Harness 就是给它画跑道。"

**核心问题**：

> "Agent 为什么需要 Harness？因为它太'自信'了。它不会说'我不知道'，而是会编一个看起来像答案的东西。这在投资分析中是致命的。"

#### Harness 的四种类型（15分钟）

**类型1：输出格式约束**

> "告诉 Agent'我要什么形式'，而不是让它自由发挥。"

- "用 Markdown 表格输出"
- "每条洞察不超过50字"
- "先给结论，再给论据"
- "分三个部分：现状、风险、建议"

**现场演示**：

- 无约束：Agent 输出一段流畅但无结构的文字
- 有约束：Agent 输出清晰的表格+要点+风险提示

**类型2：分析过程约束**

> "要求 Agent 先给分析框架、依据和不确定性，而不是只给一个看似完整的答案。"

- "先列出你的分析框架，再逐条填充"
- "对每个结论，说明依据来源和置信度"
- "在给出最终建议前，先列出所有可能的风险因素"

**教学要点**：

> "分析过程约束不仅是为了输出质量，更是为了**可审计**——你可以检查 Agent 的依据、置信度和不确定点，发现它在哪一步可能出了问题。"

**类型3：边界约束**

> "明确告诉 Agent'你不能做什么'。"

- "只基于上传的 PDF 内容分析，不要补充外部知识"
- "如果某项数据在材料中没有明确提及，标注[材料中未提及]"
- "不要给出具体的投资建议（买入/卖出/持有），只提供分析"

**现场演示"翻车教学点"**：

- 让 Agent 分析一份2023年的财报，但问它"2024年的业绩预期如何"
- **预期结果**：Agent 可能基于训练数据编造2024年数据，而不是说"材料中没有"
- **教学价值**：展示为什么边界约束是必要的

**类型4：校验机制**

> "让 Agent 自己检查自己。"

- "如果某条数据看起来异常（如毛利率超过100%），请标注[数据异常，需核实]"
- "完成分析后，请用一句话总结：'以上分析中，我最不确定的部分是...'"
- "请列出3个你可能遗漏的关键因素"

#### 扩展讲解包：Harness 要让错误暴露出来

**讲师话术**：

> "Harness 不是让 Agent 变保守，而是让错误更早暴露。一个没有 Harness 的 Agent，可能会把不确定说成确定，把推测写成事实，把材料缺口填成漂亮段落。一个好的 Harness，会逼它告诉你：哪里没有依据、哪里需要核实、哪里可能错。"

四类 Harness 可以对应四个管理问题：


| Harness 类型 | 管理问题      | 一句话模板              |
| ---------- | --------- | ------------------ |
| 格式约束       | 我怎么快速读懂？  | "用表格输出，每条不超过 40 字" |
| 过程约束       | 我怎么检查推理？  | "每个结论写依据、逻辑、置信度"   |
| 边界约束       | 它不能越过什么线？ | "只基于给定材料，未提及则标注"   |
| 校验机制       | 错误怎么暴露？   | "列出最不确定的 3 个点"     |


**现场反例：看似专业但不可审计**

```text
该公司具备较强竞争优势，未来增长空间广阔，建议持续关注。
```

讲师追问：

- "竞争优势是什么？来自哪份材料？"
- "增长空间广阔是事实还是判断？"
- "持续关注是不是已经接近投资建议？"
- "如果这个结论错了，最可能错在哪里？"

修改后的 Harness：

```text
对每个核心结论，请按以下格式输出：
结论 | 材料依据 | 推理逻辑 | 置信度（高/中/低） | 需要人工复核的问题

禁止使用"显著领先""空间广阔""确定受益"等没有依据的强判断。
如材料不足，请写[材料不足]，不要补充猜测。
```

**讲师收束**：

> "越是高层要看的材料，越不能只追求语言漂亮。我们要的是可追溯、可质疑、可复核。"

#### Harness 组合包：上午可直接让学员复制

```text
【边界】
只基于我提供的材料回答；材料未提及的信息，请标注[材料未提及]。

【格式】
优先用 Markdown 表格；每条结论不超过 40 字；先给结论，再给依据。

【校验】
输出最后列出：
1. 最不确定的 3 个点
2. 需要人工复核的 3 个数据或事实
3. 如果本分析有误，最可能的原因是什么
```

#### 教学要点总结（5分钟）

- **Harness 是安全带，不是枷锁**：好的 Harness 让 Agent 更快更准，不是更慢更死
- **防幻觉的三种方法**：
  1. 边界约束（只基于给定材料）
  2. 校验机制（自我检查）
  3. 人工复核（永远不要完全信任 Agent 的输出）
- **Harness 需要迭代**：没有一次完美的 Harness，要根据输出质量不断调整

#### 学员跟练（5分钟）

> "在刚才的 Prompt 末尾，**只加两条 Harness**：① 边界约束：'只基于我提供的材料，不要补充外部信息'；② 校验机制：'完成后用一句话说明你最不确定的部分'。再跑一遍，看 Agent 是否更'老实'。"

#### Harness 模块常见学员错误与纠偏


| 常见错误           | 为什么危险             | 纠偏方式                 |
| -------------- | ----------------- | -------------------- |
| 只写"不要胡说"       | 太抽象，Agent 不知道如何执行 | 改成"未提及则标注[材料未提及]"    |
| 只限制格式，不限制来源    | 输出漂亮但可能编造         | 加来源、页码、材料编号          |
| 要求 Agent 给最终建议 | 容易越过人的判断边界        | 改成"列出方案、条件和风险，不替代决策" |
| 没有自检           | 错误不会自动暴露          | 加"最不确定点、需核实数据、反方证据"  |
| Harness 过多过细   | 输出僵硬，任务难完成        | 保留 3-5 条关键规则，按风险排序   |

输出最后列出：
1. 最不确定的 2 个点

### 11:25-11:55 演示案例1：市场调研（30分钟，全员跟做）

> **本段要求**：学员在**自己电脑**上同步操作；讲师控节奏，每步停 30 秒等大部分人跟上。环境未就绪者跟邻座屏幕。

#### 讲师课前材料准备

**选项 A：在线搜索模式（推荐）**

- 无需准备材料文件
- 依赖 Agent 的实时搜索能力（需确认 MCP 或模型自带搜索可用）
- 优点：展示 Agent 的信息获取能力；缺点：网络不稳定时可能失败

**选项 B：离线材料模式（备用）**

准备一个 `business-school-courses.md`，包含 5 所商学院的 AI 相关课程信息摘要（课程名称、时长、核心模块、目标学员）。内容可从各商学院官网提前整理，或使用简化示例数据。

- 优点：不依赖网络，演示稳定
- 缺点：需要提前准备材料

**推荐做法**：课前测试一次在线搜索；如果不稳定，切换到离线材料模式。

#### 场景设定

> "假设中欧商学院计划开设一门'AI与产业变革'新课，我们需要快速了解同类课程的市场格局。"

#### 案例教学目标

本案例不是为了让学员记住某些商学院课程信息，而是训练一个通用动作：

```text
把一个开放式调研问题 -> 变成有边界的对比表 -> 再提炼可讨论的建议
```

讲师要反复强调：

- 调研类任务的风险不是"没有答案"，而是"答案看起来很完整但没有来源"
- 结构化表格比长篇报告更适合第一轮讨论
- 差异化建议必须基于对比，不应凭空发挥

#### 完整演示流程

**Prompt 设计（5分钟）**

展示在屏幕上，边写边讲解：

```
背景：中欧商学院计划开设一门面向高管的"AI与产业变革"短期课程，时长2天。

任务：调研全球顶尖商学院同类课程的设置情况，为课程设计提供参考。

目标商学院：哈佛商学院、斯坦福GSB、INSEAD、沃顿商学院、MIT斯隆

要求：
1. 对每家商学院，提取：课程名称、时长、核心模块、目标学员、公开价格（如有）
2. 用Markdown表格呈现对比结果
3. 基于对比，提炼3条差异化定位建议（中欧可以突出的独特价值）
4. 对无法确认的信息，标注[未确认]

约束：
- 优先使用各商学院官网的公开信息
- 不要编造课程价格或学员数据
- 如果某家商学院没有直接对应的课程，标注[无直接对应课程]
```

> "大家看这个 Prompt，它包含了 Context（中欧要开新课）、Objective（调研5家商学院）、Style（表格对比）、Audience（课程设计团队）、Constraint（不编造）。"

**Context 投喂（5分钟）**

- 方法1：让 Agent 直接联网搜索（如果配置了搜索 MCP）
- 方法2：提前准备好5家商学院的官网链接，作为 Context 输入
- 方法3：提前下载好相关网页的文本，作为文件上传

> "这三种方法的区别在于'可控性'。直接搜索最快，但 Agent 可能跑到无关页面；给链接次之；上传整理好的文本最慢但最可控。"

**离线 Context 备选（网络不稳时）**

如果课堂网络或搜索工具不可用，可改为讲师提供"模拟课程资料包"，避免实时查证：

```text
材料 A：课程官网节选，包含课程名称、目标学员、时长。
材料 B：课程大纲节选，包含核心模块。
材料 C：招生页面节选，包含价格是否公开、报名条件。
```

Prompt 中明确：

```text
以下材料为课堂练习用节选，不代表完整市场事实。
请只基于这些节选完成结构化对比，不要补充外部信息。
```

这样可以保留调研流程训练，同时避免因网络或事实更新影响课堂节奏。

**Harness 约束（5分钟）**

在 Prompt 中已经包含了约束，但可以在执行过程中补充：

```
> 请确保每家商学院的信息都标注了信息来源（官网/新闻/其他）
> 如果发现某家商学院的信息自相矛盾，请列出矛盾点并标注[需核实]
```

**输出校验与迭代（10分钟）**

- 展示 Agent 的第一次输出
- 带领学员一起检查：有没有编造的价格？有没有遗漏的商学院？对比维度是否完整？
- 演示如何迭代："我注意到沃顿的信息似乎不完整，请补充"
- 展示第二次输出，对比改进

> "这个迭代过程是最重要的。第一次输出很少完美，但通过人工校验 + Prompt 调整，第三次通常就可用。"

**校验问题清单**

让学员盯着第一次输出逐项检查：


| 检查项  | 学员要找什么         | 发现后怎么改 Prompt          |
| ---- | -------------- | ---------------------- |
| 来源   | 每个课程信息有没有来源    | "请为每行补充来源字段"           |
| 缺口   | 价格、时长、目标学员是否缺失 | "缺失信息标注[未公开]，不要猜测"     |
| 一致性  | 各学校维度是否一致      | "统一列名，不要给不同学校用不同维度"    |
| 过度建议 | 是否提出没有依据的定位建议  | "每条建议必须引用对比表中的观察"      |
| 最新性  | 是否混入未核验的新信息    | "如果不是材料中给出的信息，标注[待核实]" |


**讲师追问**

- "这条差异化建议来自表格哪一列？"
- "如果价格没有公开，Agent 有没有猜一个价格？"
- "如果让课程委员会看，最需要补充哪两个信息？"

#### 教学总结（5分钟）

- 这个案例展示了"信息收集 → 结构化对比 → 洞察提炼"的完整链条
- 强调：Agent 擅长"收集和整理"，但"差异化定位建议"需要人的判断
- 预告下午小组实战：每组会选择类似的市场调研任务，但换成自己的行业

#### 案例1 可复用 Prompt 骨架

```text
【Context】
我们正在为[组织/团队]评估[主题/机会]，需要快速了解[对标对象]的公开信息。

【Objective】
请基于我提供的材料，对[对象 A/B/C...]进行结构化对比，并提炼可供讨论的机会点。

【Audience】
输出面向[决策委员会/业务负责人/项目组]，他们时间有限，需要快速抓住差异。

【Response】
1. 输出 Markdown 对比表，列为：[维度 1]、[维度 2]、[维度 3]、信息来源、缺口。
2. 提炼 3 条初步观察，每条不超过 50 字。
3. 列出 3 个仍需人工补充的信息。

【Constraint】
- 只基于给定材料，不补充外部信息。
- 材料未提及的信息标注[未提及]。
- 不把推测写成事实。
```

### 11:55-12:25 演示案例2：财报快速解读（30分钟，全员跟做）

> **本段要求**：同上，全员在自己终端跟做；本案例重点是**故意翻车 → 加 Harness 纠正**。

> **分流说明**：本案例主线为财报解读（对 FMBA 校友/在校生高度匹配）。对于运营/行政背景的员工组学员，可选择下方"备选路径：会议纪要智能整理"跟做——教学目标相同（翻车→纠正），只是材料和场景不同。讲师大屏仍以财报主线为主。

#### 讲师课前材料准备

**必需材料**：准备一份简化的财报摘要文件 `financial-report-sample.md`，包含：

- 公司名称、报告期（如 2024 Q3）
- 营收、净利润、毛利率等 3-5 个核心指标
- 1-2 段业务亮点或风险提示
- 可使用真实上市公司财报摘要，或虚构示例数据（需标注"教学示例"）

**为什么需要准备材料**：

- 财报解读涉及精确数字，不适合依赖 Agent 实时搜索（容易编造数据）
- 本案例的教学重点是"翻车 → 纠正"，需要可控的材料环境
- 离线材料可确保每次演示的稳定性

**示例材料结构**（可复制到 `financial-report-sample.md`）：

```markdown
# 宁德时代 2024 Q3 财报摘要（教学示例）

## 核心指标
- 营业收入：XXX 亿元，同比增长 XX%
- 归母净利润：XXX 亿元，同比增长 XX%
- 毛利率：XX%
- 研发投入：XXX 亿元，占营收 XX%

## 业务亮点
- 动力电池装机量保持全球第一
- 储能业务收入同比增长超过 XX%

## 风险提示
- 原材料价格波动影响毛利率
- 海外市场竞争加剧
```

#### 场景设定

> "假设我们是某私募基金的投研团队，需要快速评估宁德时代2024年Q3的投资价值。"

#### 案例教学目标

本案例重点不是训练投资判断，而是训练高风险材料的三道防线：

```text
边界约束 -> 数据校验 -> 人工复核
```

讲师必须明确：

- 本课不提供买入、卖出、持有、目标价等投资建议
- 财务数据必须回到原始材料核对
- Agent 的价值是提取、整理、提示风险，不是替代投委会决策

#### 完整演示流程

**材料准备（5分钟）**

- 提前准备好宁德时代的财报 PDF（或文本摘要版）
- 上传给 Agent 作为外部 Context

如不希望课堂依赖真实上市公司资料，可使用匿名化练习材料：

```text
材料：某动力电池企业 2024 年三季度经营摘要（课堂练习版）
包含：营收、净利润、毛利率、现金流、管理层讨论节选。
说明：仅用于训练信息提取和校验流程，不构成投资研究。
```

这样可以减少事实核验压力，同时保留财报场景的教学风险。

**Prompt 设计（5分钟）**

```
背景：我们是某私募基金投研团队，正在评估宁德时代（300750.SZ）2024年Q3的投资价值。

任务：基于上传的财报PDF，提取核心财务指标并进行初步分析。

要求：
1. 提取以下指标（2024年Q3及同比/环比变化）：
   - 营业收入、归母净利润
   - 毛利率、净利率
   - 经营性现金流净额
   - ROE（净资产收益率）
   - 资产负债率
2. 对每项指标，用一句话说明"这个数字说明什么"
3. 识别2个最积极的变化和2个最需要关注的风险
4. 输出格式：Markdown表格 + 要点列表

约束：
- 只基于上传的PDF内容，不要补充外部信息
- 如果某项指标在PDF中没有明确披露，标注[PDF中未直接披露]
- 不要给出买入/卖出建议，只提供分析
```

**重点教学：翻车演示（10分钟）**

这是本案例的核心教学价值。

**故意不设边界约束**，让 Agent 自由发挥：

```
> 请分析宁德时代2024年Q3的财务表现
```

**预期翻车**：

- Agent 可能"自信地"编造一些数据
- Agent 可能基于训练数据补充2024年Q4的"预期"
- Agent 可能给出具体的投资建议（"建议买入"）

**翻车观察表**


| 翻车类型  | 典型表现               | 讲师追问            |
| ----- | ------------------ | --------------- |
| 编造数据  | 出现 PDF 中没有的百分比或金额  | "这个数字在第几页？"     |
| 偷换口径  | 把同比说成环比，把季度说成年度    | "它比较的是哪个期间？"    |
| 越界建议  | 给出买入/卖出/目标价        | "这是分析还是决策？谁负责？" |
| 忽略风险  | 只写亮点，不写现金流/负债/行业压力 | "反面证据在哪里？"      |
| 置信度过高 | 使用"必然""确定""显著领先"   | "材料支持这么强的判断吗？"  |


**带领学员发现错误**：

> "大家看这里，Agent 说'预计Q4营收增长15%'——PDF里有这个预测吗？没有。它'幻觉'了。这就是为什么边界约束和校验机制是必须的。"

**演示如何纠正**：

- 补充边界约束："只基于PDF，不要预测未来"
- 补充校验机制："完成后请列出你最不确定的3个数据点"
- 重新执行，对比两次输出

可直接复制的纠正 Prompt：

```text
请重新执行刚才的财报分析，但必须遵守以下规则：

1. 只基于我上传的财报材料，不使用外部知识或预测。
2. 每个财务数字后标注其来自材料中的哪一节或哪一页；如果无法定位，标注[需人工核实]。
3. 不输出买入、卖出、持有、目标价等投资建议。
4. 将输出分为三部分：
   - 核心指标表
   - 积极变化与风险
   - 不确定点与人工复核清单
5. 如果材料没有披露某项指标，请写[材料未披露]，不要自行计算或猜测，除非你明确列出计算公式和输入数据。
```

**人工复核教学（5分钟）**

- 展示 Agent 提取的财务数据
- 带领学员和原始 PDF 核对一两个关键数字
- 强调："Agent 可能把'亿'看成'万'，可能把'同比增长'理解成'环比增长'——**最终的数据准确性，必须由人负责。**"

**人工复核最小动作**

课堂上只复核 2 个数字即可，不要把时间耗在完整查账：

1. 选择一个最关键指标，如营收或归母净利润。
2. 让学员找出 Agent 输出中的数字。
3. 回到原始材料定位该数字。
4. 检查单位、期间、同比/环比口径。
5. 如果任何一项对不上，标注[需核实]，不继续推导结论。

#### 教学总结（5分钟）

- **财报分析是最典型的"高价值高风险"场景**：Agent 能极大提速，但一个数字错误就可能导致错误决策
- **防幻觉三板斧**：
  1. 边界约束（只基于给定材料）
  2. 校验机制（自我怀疑）
  3. 人工复核（最终守门）
- **Agent 的价值不是"替代分析师"，而是"让分析师把精力放在判断上，而不是搬运数据上"**

#### 案例2 可复用 Prompt 骨架

```text
【Context】
我们正在基于给定财务材料，做一份初步经营分析。材料可能不完整，所有结论都需要人工复核。

【Objective】
请提取关键财务指标，识别经营变化和风险信号，为后续人工分析提供结构化底稿。

【Audience】
输出面向投研/财务/管理团队，读者熟悉基本财务术语，但需要快速定位重点和不确定点。

【Response】
1. 核心指标表：指标 | 本期值 | 对比口径 | 材料来源 | 一句话解读。
2. 积极变化：最多 3 条，每条必须有数据依据。
3. 风险信号：最多 3 条，每条必须说明依据。
4. 人工复核清单：最需要核实的 3 个数字或判断。

【Constraint】
- 只基于给定材料，不补充外部信息。
- 不给买入、卖出、持有、目标价等投资建议。
- 数据缺失则标注[材料未披露]。
- 推断必须标注[推断]，不能写成事实。
```

#### 备选路径：会议纪要智能整理（员工组跟做）

> **适用对象**：运营/行政/市场背景学员，日常不接触财报但频繁处理会议纪要。
> **教学目标与主线相同**：故意翻车 → 发现问题 → 加 Harness 纠正。

**材料准备**：准备一份 `meeting-notes-sample.md`，包含一段 800-1000 字的会议记录原文（可虚构），内容混杂讨论、决策、待办和闲聊。

**步骤 1：故意翻车（不加约束）**

```text
请帮我整理这份会议纪要。
```

**预期翻车**：
- Agent 可能遗漏关键决策，只保留表面讨论
- Agent 可能编造不存在的行动项或负责人
- Agent 可能把讨论中的"随口一说"当成正式决策

**步骤 2：加 Harness 纠正**

```text
请重新整理这份会议纪要，遵守以下规则：

1. 输出分为四部分：关键决策、行动项（含负责人和截止日期）、待讨论事项、信息备忘。
2. 每条行动项必须在原文中有明确依据；如果原文未指定负责人或截止日期，标注[原文未指定]。
3. 不要把讨论中的建议或设想写成已确认的决策。
4. 最后列出：原文中有歧义或需要会后确认的 2-3 个点。
```

**讲师点评要点**：
- "翻车点和财报案例一样：Agent 太自信，会把模糊信息补全成确定结论"
- "Harness 的核心作用：让 Agent 暴露不确定性，而不是掩盖它"

### 17:15-17:30 总结与点评（15分钟）

#### 共性问题总结（5分钟）

基于下午巡视和汇报，提炼3-5个共性问题：

> "今天我观察到一个有趣的现象：80%的小组在第一次 Prompt 里都忘了写 Audience。这导致 Agent 的输出要么太学术，要么太口语化。记住，**同样的分析，给投委会看和给实习生看，应该是完全不同的**。
>
> 第二个共性问题是 Harness 偏弱。很多组的 Prompt 很详细，但没有明确的'边界约束'和'校验机制'。结果是 Agent 很自信地给出了一些看起来很精确、但材料里没有依据的数据。"

#### 核心认知提炼（5分钟）

用一张图总结全天：

```
驾驭 Agent = 设计好任务（Prompt）+ 管理好信息（Context）+ 设定好规则（Harness）

        Prompt（任务书）
              ↓
    Context（背景资料） → Agent 执行 → Output（输出）
              ↑
        Harness（约束护栏）

最终守门人：人（你）
```

**三句话带走**：

1. **Agent 是杠杆，不是替代**：它放大你的执行力，但不替代你的判断力
2. **质量 80% 取决于你的 Prompt，15% 取决于 Context，5% 取决于模型**：不要迷信更贵的模型，先优化你的指令
3. **永远假设 Agent 会犯错**：边界约束、校验机制、人工复核——三道防线缺一不可

### 常见翻车场景及应对


| 翻车场景         | 表现              | 应对话术                                            |
| ------------ | --------------- | ----------------------------------------------- |
| Agent 编造数据   | 给出精确但不存在的数字     | "大家注意，Agent 不'知道'自己不知道。这就是为什么要加边界约束：'只基于给定材料'。" |
| Agent 跑偏     | 输出和任务无关         | "Prompt 的目标不够聚焦。试试把 Objective 拆成更具体的子任务。"       |
| Agent 输出太长   | 信息淹没在长篇大论中      | "给 Agent 格式约束：'每条不超过30字'、'用表格呈现'。"              |
| Agent 遗漏关键信息 | 没提取出用户关心的指标     | "Context 投喂不够精准。试试先把材料做一层人工筛选，再给 Agent。"        |
| Agent 语气不对   | 太学术或太口语         | "Prompt 里加 Audience 和 Style：'面向投委会'、'资深分析师口吻'。" |

### 情绪管理

- **如果学员对 Agent 输出失望**："第一次失望是正常的。Agent 不是魔法，它需要你的引导。试着调整 Prompt，你会发现第二次好很多。"
- **如果学员过于兴奋，想完全依赖 Agent**："Agent 可以帮你写初稿，但签字的是你。最终的责任，永远在人的肩上。"
- **如果学员纠结于技术细节（如模型原理）**："这些细节很重要，但今天我们的重点是'怎么用'。课后我们可以单独讨论技术原理。"
